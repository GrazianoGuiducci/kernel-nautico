## 1. Visual thesis

The image system must make a transformation understandable before it tries to
look futuristic.

~~~text
deeper source-grounded understanding
-> one persistent yacht
-> selected change becomes visible
-> relation survives representation shift
-> consequence becomes perceptible
~~~

The visual field is allowed to be beautiful. Beauty does not substitute for
causality.

## 2. Persistent product object

One original concept yacht is the anchor.

Its design must be sufficiently distinctive to remain recognizable across:

~~~text
trace
wireframe
plan / profile / section
solid
exploded
assembly
commissioning
sea
interior/system focus
service
return
~~~

Do not copy a real Ferretti/Pershing model. A later collaboration can replace or
parameterize the concept only through authorized real product sources.

## 3. Representation states

### TRACE

Sparse line, construction geometry, first product intention.

Use for:
FORM opening, later RETURN seed.

### MODEL

Wireframe/translucent/solid controlled concept geometry.

Use for:
concept and design decisions.

### OPEN

Exploded or sectioned representation that preserves the whole product identity.

Use for:
engineering, systems, R-01 continuity and spatial reasoning.

### MATERIALIZE

Schematic/geometry acquires material, thickness, finish and assembly identity.

Use for:
transition from engineering to BUILD.

### ASSEMBLE

Macro components settle into the physical yacht.

Use for:
production/construction and commissioning.

### LIVE

The same object enters its operating environment.

Use for:
delivery, onboard relation, owner/crew/service context.

### REFLECT

The view contracts onto one operational/service relation and its consequence.

Use for:
R-01 event.

### RETURN

The consequence re-enters the organizational/product-development field.

Use for:
competence learning and next-product seed.

## 4. AI / Kernel visual signature

Avoid:

- glowing brain;
- generic neural-network halo;
- chatbot bubble as system identity;
- decorative particles that imply unexplained intelligence;
- omniscient central core;
- automatic app-to-app arrows.

Represent the Kernel through **continuity traces**.

A continuity trace is a visual relation with an identifiable origin and
destination, such as:

~~~text
source / reason -> design decision
decision -> configured object
configured object -> assembled product
product instance -> service event
event -> consequence
consequence -> reusable learning
~~~

The trace can change visual form across representations but should keep its
identity/meaning legible.

This makes AI visible as continuity and situated capability rather than an
overlay added after the yacht exists.

## 5. Reality-state grammar

The presentation may show current capability, illustrative relation and future
possibility in one field. They must not collapse.

Prefer multiple cues rather than colour alone.

Candidate cues:

~~~text
current / source-grounded relation
  stable object + solid annotation / explicit source label where needed

illustrative relation
  schematic boundary + "illustrative" in partner/technical contexts

future / horizon
  spatial distance, lighter structural completion, horizon label or deferred
  materialization
~~~

Exact styling remains open to the Design Kernel.

## 6. Camera grammar

Camera movement must preserve orientation.

Use:

- stable three-quarter hero for recognition;
- orthographic/near-orthographic plan/profile when engineering relation matters;
- controlled orbit for assembled/exploded continuity;
- macro focus only after the viewer knows where the detail belongs;
- section/interior transition with visible origin;
- environment transition that keeps the yacht as the same focus owner.

Avoid:

- camera motion used only for spectacle;
- rapid cinematic cuts that reset the product identity;
- macro details without return path;
- disorienting transitions between project and sea.

## 7. Motion grammar

Use motion to explain state change.

Preferred relation:

~~~text
origin state readable
-> transformation begins from the owning object
-> changed relation remains visible during transition
-> destination state settles
-> detail appears only after orientation
~~~

For interactive/realtime derivatives, preserve reduced-motion and static
equivalents. Direct manipulation should remain immediate; explanatory
transitions may be slower.

Do not import UI timing values mechanically into a cinematic film. Cognitive
Motion supplies orientation principles, not a universal edit tempo.

## 8. Material / atmosphere

Current concept study:
warm porcelain/ivory, bronze/gold, obsidian/dark glass, technical-paper warmth.

Status:
candidate visual atmosphere only.

Its useful qualities are:

- premium/luxury without conventional yacht-ad cliché;
- engineering clarity;
- material warmth;
- strong differentiation between object and information field;
- compatibility with solid/exploded/schematic transformations.

Do not freeze the palette until the future nautical-kernel identity and
collaboration surface are known.

## 9. Typography / annotations

Treat technical metadata as information, not texture.

Rules:

- large title text must remain editable;
- product/kernel names remain editable until approved;
- tiny labels only where the viewing scale supports them;
- use annotations to reveal relation, not to simulate engineering legitimacy;
- numerical specifications on concept frames are illustrative unless supplied by
  a qualified source;
- collaboration/investor versions should include a compact reality-state legend
  when future incarnations are depicted.
