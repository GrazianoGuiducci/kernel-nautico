# Public Kernel Visual Principle — Candidate

~~~text
formed: 2026-10-02
status: candidate cross-kernel product/design principle
first_case: Kernel Nautico
competence_state: not formed as an autonomous competence
owner_now: Kernel Nautico visual workstation + external D-ND Design / Editoriali owners
~~~

## Principle

A public kernel can have a visual-animation system that makes its operating
relations perceptible.

The function is wider than promotion.

~~~text
kernel truth
+ domain object / process
+ visual transformation
-> media presentation
-> cognitive guide
-> product demonstration
-> partner / client / investor comprehension
-> reusable surface family
~~~

The public visual does not replace the kernel or prove its capabilities by
itself.

## First case — Kernel Nautico

Kernel Nautico supplies an unusually strong first specimen because one physical
object can remain perceptually continuous while both product state and kernel
participation change.

~~~text
FORM
-> BUILD
-> LIVE
-> RETURN
~~~

The yacht is the persistent perceptual carrier.

V-01 Causal Product Continuity is the deeper semantic carrier.

The Nautical Reference Operating Model supplies technical depth beneath the
four-act public compression.

## Candidate cross-kernel structure

Do not freeze this as a universal storyboard.

The current abstract relation is:

~~~text
A. identity
B. fragmented / changing field
C. kernel participation
D. process / lifecycle traversal
E. consequence and learning
F. future capability
~~~

A later kernel may require a different morphology while preserving some or all
of these functions.

## Kernel-specific visual system

Each public kernel may need its own:

- persistent object or field;
- state/transformation grammar;
- visual signature;
- domain process/lifecycle;
- consequence-return representation;
- receiver-relative depth.

Do not reuse a yacht lifecycle merely because it worked for Kernel Nautico.

## Shared output family

A successful kernel-native visual system may project into:

~~~text
hero film
collaboration / partner deck
investor visuals
technical one-page
site animation / interaction
social clips
cognitive guide media
interactive demonstrator
~~~

The same truth owner can support several visual projections without one
projection becoming the canonical ontology.

## Current visual invariant from KN

The strongest candidate invariant is not a style.

It is:

> meaningful relations remain perceptible while the represented object or field
> changes state.

For Kernel Nautico that means source/reason, configuration, product identity,
event, consequence and competence can remain connected across FORM/BUILD/LIVE/
RETURN.

## Relation to technical depth

The public animation should not expose every production phase.

Instead:

~~~text
Nautical Reference Operating Model
-> technically credible internal understanding
-> selected visual state changes
-> simple public narrative
~~~

Technical depth exists so that visual simplification is informed, not arbitrary.

## Evidence required before generalization

Do not promote this candidate into a shared Design competence until at least:

1. the Kernel Nautico hero/master is exercised;
2. the same source system produces useful deck/one-page/social derivatives;
3. receiver readback shows what actually improved comprehension;
4. a second non-identical public kernel uses the principle;
5. the reusable difference survives the change of domain.

Then return the learned method to D-ND Design Kernel / Editoriali / Meta_Skill
as appropriate.

## Boundary

This principle authorizes no publication, advertising campaign, rendering stack,
brand system or new competence by itself.

It preserves a candidate relation for real visual work to test.
