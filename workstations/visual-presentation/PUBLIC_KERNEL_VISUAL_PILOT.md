## Operator determination

Every new public kernel will have its own **3D Visual Animation**.

The animation is not treated as decorative launch media. It is a public
presentation surface through which a receiver can understand:

- how the kernel is used;
- which processes it can participate in;
- the phases through which its field changes;
- how the kernel itself can evolve through work;
- the larger possibilities opened by the kernel;
- the different kinds of value it can create or preserve.

The same visual system can support:

~~~text
public first encounter
+ media presentation
+ cognitive guide
+ investor explanation
+ prospective-client explanation
+ collaboration / partner discussion
+ deck / one-page / site / social derivatives
~~~

## First pilot

Kernel Nautico is the first complete pilot.

Ferretti / Pershing is the first strategic company case through which the
nautical presentation will be pressure-tested.

Keep the distinctions explicit:

~~~text
Kernel Nautico

Kernel Nautico
~~~

The visual master must therefore work first as a truthful Kernel Nautico
presentation and later support a Ferretti-specific collaboration cut without
making Ferretti the identity of the kernel.

## Shared presentation function

Across public kernels, the reusable function is:

~~~text
kernel truth / identity
-> recognizable visual object or field
-> use / process becomes perceptible
-> state and evolution become perceptible
-> consequences and value become perceptible
-> larger possibility remains reachable
-> receiver can understand where to go deeper
~~~

This is a **presentation function**, not a fixed visual template.

A future Social Kernel, Product Kernel or another public kernel must not inherit
a yacht, exploded hull, technical dossier, FORM/BUILD/LIVE sequence or another
Kernel Nautico-specific morphology merely because the first pilot used it.

## Kernel-specific incarnation

Each kernel forms its own visual grammar from:

~~~text
its real object
+ its processes
+ its state changes
+ its competence/evolution relation
+ its receiver
+ its value field
+ its public identity
-> kernel-native 3D visual animation system
~~~

The common requirement is cognitive legibility through motion and spatial
representation. The visual metaphor remains kernel-native.

## Public-kernel value field

The visual system should be able to make several kinds of value distinguishable
without turning them into unsupported ROI claims.

### Understanding value

The receiver can understand what the kernel is and how it differs from a
generic assistant/tool.

### Operating value

The receiver can see how the kernel participates in work, sources, decisions,
state and process.

### Continuity value

The receiver can see what remains connected while work or the represented
object changes state.

### Competence value

Experience can produce a reusable difference that changes later capability.

### Integration value

A public kernel can become situated in a real organization without pretending
that the public repository already contains the company.

### Lifecycle value

Where the domain has a lifecycle, the relation can continue after an initial
project or delivery.

### Strategic possibility value

The presentation can show a credible direction beyond current capability while
keeping present, direction and horizon distinct.

### Economic / collaboration value

Business-specific cuts can show why deeper integration, co-development or
stewardship may become valuable. Pricing, ROI and commercial claims remain with
their evidence and owners.

The master should be modular enough that these forms do not require inventing a
second product story.


The visual signature of the Kernel remains:

> meaningful relations remain reachable while the product changes state.

## Learning threshold

This operator determination is now a stable presentation requirement for public
kernels.

The **production method** is not yet a new competence.

Kernel Nautico is the first exercise. A later non-identical public kernel should
test what actually transfers:

~~~text
public-kernel presentation function
artifact family
value field
cognitive-motion principles
learning-return method
~~~

and what was merely nautical-specific.

Reusable design learning returns to the D-ND Design Kernel. If real production
exposes a distinct continuing 3D method that existing Design faculties cannot
carry, only then form the smallest new owner-native competence.
