## Why this case is non-identical

V-01 Exercise 01 formed Lifecycle Return Qualification from a company-internal
after-sales / failure / product-improvement relation.

Wheelyboat 123 breaks that morphology.

Official MAIB source:
https://www.gov.uk/maib-reports/capsize-of-recreational-craft-wheelyboat-123-with-the-loss-of-2-lives

MAIB found that the craft had not been correctly maintained; degraded bow-ramp
seals allowed water ingress and loss of stability. The activity centre had not
fully identified the risks of operating the craft with wheelchair users. The
activity centre and care home also each assumed the other held relevant
knowledge.

The recommendations were distributed across:
- local-government / oversight relation;
- South West Lakes Trust for maintenance and operation;
- Burdon Grange care home for external-activity risk assessment;
- The Wheelyboat Trust for safe operation and use guidance.

The MAIB publication also identifies an oversight gap around charitable
waterborne activity:
https://www.gov.uk/government/news/wheelyboat-123-report-published

## Pressure on the existing capability

Lifecycle Return Qualification v0.1 assumed a useful return could be expressed
as a reusable difference going to the closest competent owner.

This case exposes a wider relation:

~~~text
one consequence
-> several causal seams
-> several legitimate owners
-> different corrective / learning returns
-> one interface or oversight gap can itself be causal
~~~

Collapsing these into one "lesson learned" would destroy source, authority and
action meaning.

## Evolved resultant — Lifecycle Return Qualification v0.2

~~~text
event / consequence
+ vessel / product state
+ causal factors
+ source / time / evidence
+ owner / authority map
-> decompose return paths

for each material causal seam:
  local state | corrective action | reusable difference | retained unknown
  -> responsible owner(s)

if the material cause is in the relation between owners:
  -> preserve interface / handoff / oversight gap as its own return object

only reusable differences:
  -> change the competent owner(s) / competence relation
  -> alter later work
~~~

Important distinctions:

~~~text
same event
!= same return for every owner

several owners
!= shared authority over every action

missing ownership
!= permission for Kernel Nautico to assume authority

recommendation
!= competence

safety consequence
!= product-only consequence
~~~

## Case decomposition

~~~text
craft condition / maintenance
-> maintenance regime / condition monitoring owner

operator recognition / response
-> operating procedure / training owner

wheelchair-user risk
-> activity / disability-awareness / risk-assessment owners

manual / safe-use guidance
-> craft guidance / design-support owner

assumed knowledge between organizations
-> interface / handoff relation

oversight grey zone
-> governance / oversight relation
~~~

This decomposition is a Kernel Nautico interpretation of the MAIB evidence; it
does not assign legal blame or transfer the MAIB's authority.
